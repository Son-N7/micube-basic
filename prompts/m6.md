# 6번 모듈 실습 프롬프트 — SQL 리팩토링

- 시작 지점: 태그 `m6-start`. 5번 모듈 모범 답안(버그 수정, 테스트 보호 hook, 위험 SQL 3중 방어, 컨벤션 hook)과 팀원이 옮겨 온 재고 현황 API(`GET /api/stock-summary`)가 들어 있습니다.
- 코드 블록을 그대로 복사해 붙여넣습니다. **[터미널]** 표시는 터미널에, 나머지는 Claude Code 입력창에 입력합니다.
- Claude가 답 끝에 "진행할까요?"처럼 물어도, 다음 프롬프트가 그 답을 대신하면 그대로 다음 프롬프트를 입력합니다.
- 결과물: 결과 고정 테스트 `StockSummaryResultLockTest`, 리팩토링한 매퍼, `docs/refactoring-review.md`
- 늦어졌다면 지금까지 한 작업을 커밋하고 `m6-lock-done`(결과 고정 테스트 완료)에서 새 브랜치를 만들어 STEP 04부터 합류합니다 (**[터미널]**).
  ```
  git add -A
  git commit -m "chore: 6번 진행 중"
  git switch -c practice/m6-lock m6-lock-done
  ```

## 대상

`src/main/resources/mapper/stock/StockSummaryMapper.xml`의 `selectStockSummaryList`. 구 시스템 화면 쿼리를 그대로 옮긴 것이라 지금은 정확하지만 읽기 어렵고 느립니다. 결과(행 수·값·정렬)를 바꾸지 않고 고치는 것이 목표입니다. AI의 "결과는 같습니다", "더 빠릅니다"를 테스트와 측정으로 확인합니다.

## STEP 03. 결과 고정 테스트 먼저

```
리팩토링 전에 지금 쿼리의 결과를 고정하는 테스트 StockSummaryResultLockTest 를 새 파일로 만들어 줘.
- 파라미터 조합 6개 이상: 분류 전체/하나, 기준월 있음/없음, 상품코드 일부 일치
- 테스트 데이터에 보류 없는 로트, 사유 두 개가 걸린 로트, 해제된 보류만 있는 로트, 소비기한 없는 로트, 소진 로트를 넣어 경계를 만든다
- 지금 쿼리로 나온 결과(행 수, 각 행의 값, 정렬)를 기대값으로 저장한다
- 실행해서 통과하는 것을 보여 줘
제품 코드는 수정하지 마.
```

테스트를 읽어 보고 맞으면 고정합니다. 편집기에서 `.claude/protected-tests.txt` 끝에 새 테스트의 경로(`git status --short`에 보이는 경로)를 한 줄 추가합니다. 5번 모듈의 테스트 보호 hook이 리팩토링 중에 이 테스트를 고치지 못하게 막습니다.

## STEP 04. 계획 → 리팩토링

```
selectStockSummaryList 를 리팩토링하려고 해. 가독성(<sql>/<include>, 별칭, 중복 제거)과
인덱스를 쓸 수 있는 조건으로의 변경을 담은 계획을 먼저 보여 줘. 기준월 조건은 <bind>로 월초와 다음 달 월초를 만들어 범위 조건으로 바꿔.
결과(행 수·값·정렬)는 바뀌면 안 돼.
StockSummaryResultLockTest 는 수정하지 마. 내 확인 전에는 고치지 마.
```
```
확인한 계획대로 고쳐 줘. 계획에서 나에게 물어본 것은 추천안대로 하되, 지금 결과와 달라지는 추천안은 빼고 지금 결과를 유지하는 쪽으로 해. 고친 뒤 StockSummaryResultLockTest 와 전체 ./gradlew test 를 실행해 줘.
고정 테스트가 실패하면 고치기 전에 어떤 조합에서 무엇이 달랐는지와 원인 구문부터 설명해 줘.
```

끝난 뒤 확인
- `StockSummaryResultLockTest`는 수정되지 않았다 ([터미널] `git diff -- src/test` 결과가 비어 있다). Claude가 고치려 했다면 테스트 보호 hook의 메시지가 응답에 있다
- 기준월 조건이 `YEAR()`·`MONTH()` 대신 범위 조건이다
- 계획에서 "결과가 달라질 수 있다"고 한 항목이 있으면, 실제 조건식이 설명과 같은 범위인지 본다
- 응답에 5번 모듈 hook(check-mapper) 결과가 있다. 계획 단계에서 NOLOCK 누락·`SELECT *`를 이미 고쳤다면 hook은 조용히 통과합니다

## STEP 05. 측정

```
개발 DB(로트 20만 건)에서 리팩토링 전·후 쿼리를 비교해 줘.
- 전 쿼리는 git show m6-start:src/main/resources/mapper/stock/StockSummaryMapper.xml 을 .local/old/StockSummaryMapper.xml 로 꺼내
- 측정용 파라미터 JSON을 하나 만들고(분류 FRESH, 기준월 2027년 3월), node scripts/render-sql.mjs 에 --inline 을 붙여 전·후 SQL을 만든다 (전 쿼리는 --xml .local/old/StockSummaryMapper.xml)
- 만든 SQL을 파일로 저장해 node scripts/db.mjs --env dev --file 로 전·후를 번갈아 4번씩 실행하고(첫 번째 쌍은 준비 실행으로 빼고), 나머지 3번의 DB 실행 시간과 행 수를 비교해 줘
- 같은 SQL의 EXPLAIN 결과에서 인덱스를 어떻게 쓰는지 비교해 줘
- 측정 조건, 명령, 결과 표를 .local/bench/result.md 에 저장해 줘
측정하지 않은 개선은 주장하지 마. H2 결과라 MSSQL과 다를 수 있다고 표시해 줘.
```
