```
docs/design/SHOP-FD-012-sales-hold.md 와 실제 소스(Controller, Request, Service, 매퍼 XML, ErrorCode, 테스트)를 대조해 줘.

어느 쪽을 고쳐야 할지는 정하지 말고 사실만 보여 줘. 파일은 수정하지 마.
```

## STEP 02. 같은 대조를 `claude -p`로

```
방금 대조를 사람이 묻지 않아도 돌릴 수 있게 scripts/fd-check.mjs 를 만들어 줘 (Node.js, Mac·Windows 공통).
- 인자로 받은 정의서 경로로 claude -p 를 실행한다. 셸을 거치지 말고 scripts/lib/run.mjs 의 run() 으로 인자 배열을 넘겨서 따옴표 문제가 없게 해 줘
- 옵션: --output-format json, --json-schema(issues 배열: item, spec, source, location, verdict 불일치|확인 필요),
  --permission-mode dontAsk, --allowedTools "Read,Grep,Glob", --max-turns 30
- 결과 JSON의 structured_output 을 reports/fd-<정의서 이름>.json 으로 저장하고 불일치 개수를 출력한다
옵션마다 왜 필요한지 주석으로 짧게 남겨 줘. 만든 뒤 실행은 내가 터미널에서 할게.
```

**[터미널]**
```
node scripts/fd-check.mjs docs/design/SHOP-FD-012-sales-hold.md
```

1~3분 걸립니다. STEP 01 표와 `reports/fd-SHOP-FD-012-sales-hold.json`을 나란히 놓고, 한쪽에만 있거나 판정이 다른 항목을 찾습니다. 개수는 실행마다 조금씩 다를 수 있습니다. 이 차이가 STEP 03 원칙("기계로 판정되는 검사는 AI에게 맡기지 않는다")의 이유입니다.

## STEP 03. 커밋 전 검증 스크립트

```
scripts/precommit-check.mjs 를 만들어 줘 (Node.js, Mac·Windows 공통).
1. git diff --cached --name-only 로 커밋할 파일을 구한다
2. 매퍼 XML이 있으면 scripts/check-conventions.mjs 로 C1~C3 를 검사한다
3. ./gradlew test 를 실행한다 (scripts/lib/run.mjs 의 runGradle() 로)
4. --with-ai 옵션이 있을 때만 scripts/fd-check.mjs 를 docs/design/ 의 정의서(SHOP-FD-*.md)마다 실행한다
5. 결과를 docs/design/code-review-template.md 양식으로 reports/code-review-YYYYMMDD-HHmmss.md 에 쓴다
6. 컨벤션 위반이나 테스트 실패가 있으면 종료 코드 1로 끝낸다
기계로 판정되는 검사는 AI를 부르지 않는다는 원칙을 파일 머리 주석에 적어 줘.
그리고 .githooks/pre-commit 에서 이 스크립트를 부르게 만들어 줘.
확인할 때 테스트나 매퍼 파일은 바꾸지 말고, --with-ai 실행도 하지 마 (위반 확인은 다음 단계에서 내가 직접 할게).
```

**[터미널]** hook 경로를 지정하고 실행 권한을 줍니다 (Claude가 만든 파일에는 실행 권한이 없어 git이 hook을 건너뛸 수 있습니다).
```
git config core.hooksPath .githooks
chmod +x .githooks/pre-commit
git add --chmod=+x .githooks/pre-commit
```

**[터미널]** 스크립트와 hook을 커밋합니다 (매퍼가 없는 커밋이라 테스트만 돌고 통과합니다).
```
git add -A
git commit -m "chore: 커밋 전 검증 스크립트"
```

## STEP 04. 마지막 관문 확인 (5번 모듈 회수)

① 컨벤션 위반이 커밋을 막는지

**[터미널]** 이번에는 사람이 편집기로 직접 `src/main/resources/mapper/product/ProductMapper.xml`의 `WITH (NOLOCK)` 하나를 지우고 저장한 뒤 커밋해 봅니다.
```
git add src/main/resources/mapper/product/ProductMapper.xml
git commit -m "test: 커밋 전 검사 확인"
```

커밋이 막히고 `reports/`에 코드검토서 초안이 생기는지 봅니다. 확인 뒤 되돌립니다.
```
git restore --staged src/main/resources/mapper/product/ProductMapper.xml
git restore src/main/resources/mapper/product/ProductMapper.xml
```

② AI 대조까지 넣어 한 번 돌려 보기

커밋 때마다 도는 검사에는 AI를 넣지 않았습니다. STEP 02의 헤드리스 검증기가 커밋 전 검사 안에서도 잘 도는지 `--with-ai`로 직접 확인합니다.

**[터미널]**
```
node scripts/precommit-check.mjs --with-ai
echo $?
```

1분 안팎 걸립니다 (`claude -p` 실행). 새로 생긴 `reports/code-review-…md`를 열어 봅니다.

| 확인 | 기대 결과 |
|---|---|
| 1절 기계적 검사 | 컨벤션·테스트 통과 |
| 2절 기능정의서 대조 (AI) | 정의서·소스·판정·위치가 채워져 있고, STEP 01에서 찾은 불일치(`LOT_SOLD_OUT`, `HOLD_REASON_INVALID`, comment 200자/500자, SOLD_OUT 분기, UT-10)가 들어 있다 |
| 3절 판정과 `echo $?` | "커밋 가능 여부: 가능", 종료 코드 0. AI가 찾은 불일치는 커밋을 막지 않고 사람이 판단할 목록으로 남는다 |

## STEP 05. 산출물 문서 작업 (15분)

검사만이 아니라 프로젝트 산출물 문서도 코드와 테스트 결과에서 바로 만듭니다. 사실(테스트 결과, 코드)은 파일에서 가져오고, AI는 연결과 문장만 맡깁니다.

① 단위테스트 결과서

**[터미널]** 결과서의 근거가 될 테스트 결과를 새로 만듭니다.
```
./gradlew test
```

```
docs/design/SHOP-FD-012-sales-hold.md 6절의 단위테스트(UT-01~UT-10)마다 실제 테스트 메서드를 찾아 연결하고,
build/test-results/test/ 의 결과 XML로 단위테스트 결과서를 docs/design/SHOP-FD-012-ut-result.md 로 써 줘.
열: UT ID / 시나리오 / 테스트 클래스·메서드 / 결과(통과·실패·테스트 없음) / 비고. 맨 위에 실행 일시와 통과·실패·없음 개수.
결과는 XML에 있는 것만 쓰고, 연결할 테스트가 없으면 '테스트 없음'으로 남겨. 테스트 코드는 고치지 마.
```

끝난 뒤 확인
- 결과서의 통과 개수가 XML과 같다 (몇 개만 골라 대조)
- UT-10은 '테스트 없음'으로 남았다 (STEP 01 불일치 4번과 같은 내용)

② 기능정의서 갱신

STEP 01 대조에서 정의서 쪽이 틀렸다고 판단한 항목만 정의서에 반영합니다. 어느 쪽을 고칠지는 사람이 정합니다. `<정의서를 고칠 항목>`은 STEP 01 표에서 골라 씁니다 (예: 남은 보류가 없을 때 수량 0이면 SOLD_OUT이 되는 분기).
```
docs/design/SHOP-FD-012-sales-hold.md 를 코드 기준으로 고쳐 줘. 고칠 항목은 아래뿐이야.
- <정의서를 고칠 항목>
버전을 1.3으로 올리고, 맨 아래에 변경 이력 표(버전 / 일자 / 변경 내용 / 근거 파일:줄)를 만들어 이번 변경을 적어 줘. 다른 항목과 코드는 고치지 마.
```

**[터미널]** 두 문서를 커밋합니다 (매퍼가 없는 커밋이라 커밋 전 검사는 테스트만 돕니다).
```
git add docs/design
git commit -m "docs: 판매 보류 단위테스트 결과서와 기능정의서 1.3"
```

## STEP 06. SVN과 CI로 옮기기 (설명)

- SVN: TortoiseSVN 클라이언트 hook(Pre-commit)이나 서버 `pre-commit` hook에서 같은 `node scripts/precommit-check.mjs`를 호출합니다.
- CI: 같은 명령을 CI 단계로 실행하고 종료 코드로 실패를 판정합니다. AI 대조(`--with-ai`)는 시간·비용 때문에 수동 실행이나 CI의 별도 단계로 둡니다.
