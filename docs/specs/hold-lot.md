# 판매 보류 등록 API

품질팀이 문제가 생긴 로트를 직접 판매 보류할 수 있게 한다. 지금은 품질팀 요청을 받아 개발자가 DB에 직접 넣고 있다.

## API

`POST /api/lots/{lotNo}/holds` — 역할 `QC`

요청 본문

| 항목 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `reasonCode` | 문자열 | O | `QUALITY`(품질) 또는 `CLAIM`(고객 클레임) |
| `comment` | 문자열 | O | 보류 사유 설명. 공백만 있는 값 불가, 500자 이내 |

응답: 201, 로트 (`LotResponse`)

## 처리

1. 로트가 없으면 404
2. 소진(SOLD_OUT) 로트는 보류할 수 없다
3. 같은 로트에 같은 사유의 활성 보류(해제되지 않은 보류)가 있으면 거부한다. 다른 사유의 보류는 함께 걸 수 있다
4. `stock_hold`에 보류 1건을 기록한다 (사유, 코멘트, 보류 일시, 보류한 사용자)
5. 로트 상태를 HOLD로 바꾼다. 수량은 바꾸지 않는다
6. 4·5는 한 트랜잭션

## 오류

| 상황 | HTTP | 오류 코드 |
|---|---|---|
| QC 역할 아님 | 403 | `FORBIDDEN` |
| 로트 없음 | 404 | `LOT_NOT_FOUND` |
| 소진 로트 | 409 | `LOT_NOT_HOLDABLE` |
| 같은 사유의 활성 보류가 이미 있음 | 409 | `HOLD_ALREADY_EXISTS` |
| `reasonCode` 없음·잘못된 값, `comment` 없음·공백·500자 초과 | 400 | `INVALID_REQUEST` |

## 확인 시나리오

| # | 요청 | 기대 |
|---|---|---|
| 1 | QC가 `LT-261001-0001`에 `QUALITY` 보류 | 201, 상태 HOLD, 수량 40 그대로, 활성 보류 1건 |
| 2 | 1 다음 같은 요청 다시 | 409 `HOLD_ALREADY_EXISTS`, 보류 1건 그대로 |
| 3 | 1 다음 `CLAIM` 보류 | 201, 활성 보류 2건 |
| 4 | WAREHOUSE가 보류 | 403, 데이터 변화 없음 |
| 5 | `comment`가 공백 | 400, 데이터 변화 없음 |
| 6 | 소진 로트 `LT-261006-0014` 보류 | 409 `LOT_NOT_HOLDABLE` |
